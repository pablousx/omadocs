# Security policy

Security fixes target the latest release and the default branch. Older releases do not have a separate maintenance commitment.

Report vulnerabilities involving Google account credentials, document handling, local storage, or release integrity through [GitHub private vulnerability reporting](https://github.com/pablousx/omadocs/security/advisories/new). Do not open public issues or pull requests with vulnerability details.

Include affected versions, a minimal reproduction using fake data, expected impact, and any proposed mitigation. Never attach live credentials, private files, or recovery records containing user data. Allow maintainers time to investigate and coordinate a fix before public disclosure; no response deadline or bug bounty is promised.

Ordinary support questions belong in issues after removing private information. See the README for the project's security boundaries and supported behavior.
